1. **树影下从 9-19 起再也没有条目**（往日列表实锤：最新只到 09-18；而总结书签一路照推 838→1194、日志零 FAIL）；

## ✨ 本版内容（四件 · 5 文件 17 处）

### 件① 树影下「记成功不落盘」根治（本版最重要）

症状是「页面全空、日志全绿」：总结流程**记了成功、推了书签，却一条都没写进库**。两条通道一起堵：

- **取服务不再永久缓存 null**：原来 `by lazy { try { get<TreeShadowService>() } catch { null } }` 会把一次失败钉死整个进程生命周期（保活让进程几天不重启），而写入点是空安全调用 → 静默跳过。改成 getter，失败下次重试。
- **记账与开关解耦**：段末时钟 `KEY_LAST_USER_MSG_AT` 与跨天兜底归档原来和「助手树影下开关」捆在一起；开关为 false 时时钟冻结 → 条目全写进同一个旧日期桶，且归档同时停摆 → 那个桶「今天」「往日」都看不见。现在**簿记永远执行**，只有章节轮转仍听开关。
- **写入改非空依赖 + 落盘核验**：取不到服务＝记 FAIL 且游标不动；写入后**回查该日期是否真有这条**，只有真落盘才推书签。
- **补成功日志**：新增 `OK: summary saved (total=…, chars=…, date=…, conv=…)` —— 此前成功是零留痕的，所以「成功」和「静默跳过」在日志里长得一模一样。

### 件② 主动消息流式落库节流（热点 A）

主动消息**每收到一个流式分片**就把整个会话的**全部消息节点**重新 JSON 编码一遍、再回读比较（1163 节点 × 每次分片）。现在流式途中**≥1.5 秒才落库一次**，内存态仍每分片更新（界面照常实时），收尾照旧强制全量落库。

### 件③ onTrimMemory + 图片内存缓存上限

- Coil 内存缓存默认按可用堆的 25% 走（largeHeap 下可达 ~128MB）且**只涨不落**（保活让进程不重启）→ 压到 **15%**。
- 新增 `Application.onTrimMemory`：系统从 `TRIM_MEMORY_RUNNING_LOW` 起就把图片内存缓存吐掉（磁盘缓存保留）。这是「保活不倒」一直缺的另一半。

## ⚠️ 已知未修（延期到开题后）

- **B4 热窗口 / session 治理**：唯一能让 5500 条窗口不再整份常驻堆的那一刀，**需要 B0 两组 heap dump 定向**（她插 USB，树抓判读）。渲染仍有卡顿延迟 = 方向对但未根治。
- **B1/B6 尾部加载**：B6 经复读判定**不能单独做**（`ProactiveMessageService` 的整份加载是「防流式覆盖历史」的承重设计），必须随 B4 一起。
- **图片缓存时效（P1）**：进程退后台即清空图片内存缓存 —— 她的原话是「不要每一张图片都塞进运行内存，只需要上下文里的图片」。
- **L11 后台工具面缺 `workflow_*`**：主动消息链里树想创建/修改工作流会直接 `workflow_create NOT FOUND`，只能退化成 `set_alarm`（9-19 / 9-20 稳定复现）。
- 遗留账 L1~L12 见任务书。
