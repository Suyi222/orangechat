## 🔥 这版在治什么

9-26 B0 真机取证定案（三组对照实验 + hprof 类直方图，证据链闭环）：

- **真凶**：`data/ai/AILogging.kt` 的 `AILoggingManager` 保留最近 **32 条**生成日志，每条攥着**一整份请求 messages**——而 messages 是每轮生成从数据库解码出来的**新对象**（不是共享引用）⇒ **每生成一次就多囤一份「整会话副本」**；淘汰只看条数不看字节。
- **量级**：她的 5093 条会话一份副本 ≈ **29MB** ⇒ 512MB 堆 ÷ 29MB ≈ **17 次生成就 OOM**。会话越大炸得越快，所以偏偏是她。
- **它解释了三件事**：「卡在回复时」「越用越坏」「清后台就好」（进程被杀 = 副本清零）。
- 与图片无关（纯文字对照 +31.3/+29.5/+26.2MB ≈ 带图 +30.2/+28.3/+29.2MB）、与会话常驻无关（force-stop 重开同一会话仅 18MB）、不是垃圾（send-trim-memory 后 266.9MB 一动不动）。

## ✨ 本版内容（三条修法 · 6 文件）

### 件① 日志不再持有完整 messages（修法①）

`AILogging.Generation` 从「整份请求体」重写为**瘦身摘要**：

- 参数元数据（模型/温度/topP/maxTokens/推理档）+ **工具只留名字列表**（旧实现 113 个完整 schema 常驻）；
- 末尾 **6 条**消息摘要：文本截断 **160 字**；附件只留**类型 / 字节数 / 采样 hash**（`image 312.4KB sha1:ab12cd34`），data URL、文件、网络 URL 三态识别；
- provider 只留名称 + baseUrl，**apiKey 永不进日志**；
- 对 messages / tools schema / providerSetting **零引用**——副本从此无处生根。

### 件② 淘汰改字节预算（修法②）

双保险：条数上限 32 + **总驻留 ≤16MB**（超出从最旧丢起）。每条日志自报 `estimatedBytes`（持有字符串 ×2B + 对象头），开发者页卡片直接显示「驻留 ~XKB」——瘦没瘦一眼可验。按新摘要形态，32 条满打满算 ≈ 百 KB 级，预算闸是防未来回归的保险丝。

### 件③ 完整请求体按需落盘（修法③ · 网关测试/D1 基建就位）

开发者页新增**「请求体落盘（网关取证）」开关**（默认关）：打开后每次生成把完整请求体（messages 全文 + tools 完整 schema + 参数）异步写到 `filesDir/ai_request_dump/req_时间戳.json`，写完即释放内存引用。脱敏规则：provider 只写类型/名称/baseUrl。她的「两平台请求体对比」网关测试从此**不需要任何常驻内存**——要用时打开开关，用完即关。

### 件④ 还原与收尾

- `build.gradle.kts` 的临时 `isDebuggable=true`（B0 取证用）**已还原**，diff 核验只剩版本号两行；
- 开发者页日志卡片原本是**空壳**（Card 里什么都没有）→ 现在展示摘要全文，日志第一次真正可读；
- versionCode 170 → **171**、versionName 2.4.6.3 → **2.4.6.4**。
