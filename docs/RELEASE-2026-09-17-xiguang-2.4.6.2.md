## 🔥 这版在治什么

9-17 装机实测反馈 4 条 + 树邮局晨信案，逐条复查 2.4.6 全部改动后定案三个 bug：

- **Bug C（实锤 · 树影下罢工真凶）**：「已总结到第几条」的书签是**全局单键**——5500 条大窗口一次成功总结就把书签顶到 5500+，之后所有正常窗口永远 `total ≤ 书签` 被**静默跳过**（不写日志、不记失败）。她导出日志时弹「还没有失败日志，说明自动总结一直正常」= 装机以来零失败记录 = 实锤。2.4.6 止血成功（大窗口总结首次跑得动）反而让这颗 2.4.5 埋下的雷显形。
- **Bug A（设计缺陷 · 照修）**：总结失败退避把「内容拒收」（总结为空/超 200 字，确定性失败）也计入基础设施阶梯，一路爬到 240 分钟封顶 + 提示是一次性的 = 迟早复发的「无声罢工」。
- **Bug B（健壮性回退 · 照修）**：H4 尾查询 `ORDER BY … LIMIT 1` 走排序，`json_extract` 在排序前对**全部节点行**求值（SQLite 3.49.1 实证）——一行坏数据毒全局、巨窗口每次白解析全部 blob；null 又让工作流 LastChatAgo fail-open、主动消息闲置分钟数恒溢出，双向不稳。
- **特殊 token 泄露依旧（命中不稳定）**：vc168 不含 Reasoning 清洗补丁属预期；「命中不稳定」新确诊一条根源——反引号奇偶性误判（正文里奇数个单反引号会让其后所有 token 被当作「示例代码」原样放行）。

## ✨ 本版内容（六件）

### 件①（RC）树影下罢工根治：书签按会话存

- **RC1**：`segment_base_count` 改 **`segment_base_count_<会话id>`** 独立键——大窗口总结不再锁死别的窗口；冷启动 0 安全（回退最近 12 条），旧全局键作废不迁移。
- **RC2**：静默跳过路径**也写总结日志**（`SKIP: no new messages (total=X, base=Y, conv=Z)`）——这次诊断若有这行，一眼定案。
- **RC3**：导出 Toast 文案修正——「还没有失败日志，说明一直正常」在静默跳过状态下恰恰是错的。
- **RC4**：章节轮转计数同样改按会话存（旧全局键跨窗口聊天互相污染计数）。

### 件②（RA）总结退避缺陷修复

- **RA1**：内容拒收（总结为空/过长）**不再与基础设施失败共用退避阶梯**——不设退避窗口，改**缩窗重试**（总结窗 60→30→12 条逐级缩小，输入短则输出短），成功即复位。
- **RA2**：**熔断替代无限退避**——连续失败 ≥5 次显式暂停 24 小时（时间线插「⏸️ 自动总结已暂停：原因」），到期自动探测一次；显式停摆胜过无声罢工。
- **RA3**：提示持久化——「只提示一次」的 boolean 改**按日重发**：持续失败每天往**当天**时间线插一条（旧版第二天看当天时间线一条没有）。
- **RA4**：退避/暂停期间**章节计数照常推进**（旧版连计数都停了，章节边界漂移）；命中但暂停时写 SKIP 日志，消息不丢、恢复后整段补总结。

### 件③（RB）最后消息时间健壮性

- **RB1**：尾查询改**两段式** `WHERE node_index = (SELECT MAX(node_index) …)`——`json_extract` 只解析最后一行；一行坏数据不再毒全局，巨窗口不再每次白干（工作流条件评估每次触发都跑这条）。
- **RB2**：查询异常 / null / 时间不可解析 → **回退 `conversationentity.update_at`** + Log.w（2.4.6 风险表 #4 原定对策，当时未落地，这次补上）。
- **RB3**：主动消息 `idleMinutes` 维持 MAX_VALUE 兜底语义不变（hotfix 批不动触发行为），但 null 出现**必写 proactive_trace 日志**——发生频率就是 beta.2 要不要改「宁可不发不误发」的证据。

### 件④（token 全层）特殊 token 五层盖满，不赌单点

1. **源头清洗**：`ChatCompletionsAPI.parseMessage` 解析 delta 时直接剔除控制 token——最靠近源头，一次覆盖流式/非流式/SSE-merge 全路径。
2. **跨 delta 尾巴暂扣**：每条流一个 `StreamTokenBuffer`——未闭合的半截 token（`<|begin_`）**押着不下发**，等下一个同类型 delta 拼上再洗；专治「Tool/Reasoning part 打断 Text 拼接，半截 token 拼不回来白白放过」（逃逸假设②）。
3. **围栏状态机修正**（逃逸假设④）：行内 `code` 保护**不跨行**——奇数个反引号不再污染其后全文判定（这就是「命中不稳定」的根源之一）；``` 围栏维持整块保护。
4. **sanitizeFinal 终态清洗**：流尾/落库/渲染三个「等不到下一包」的时点，把文末未闭合的 `<|xxx` 尾巴**直接剥掉**（不剥就是永久残留进库）。
5. **渲染兜底 + 存量清污**：上屏前对正文/思考统一终态清洗（聊天页 + 导出图）；**一次性清扫历史脏数据**——启动时后台扫 `message_node` 中含 `<|` 的行、按同规则清洗回写（只动脏行，正常库近零开销），断「脏历史发回模型 → 模型模仿复吐 → 指令遵循退化」的自我强化循环（晨信案嫌疑⑥同案）。
- 随包带出：`6f8cba96` Reasoning（思考流）清洗（2.4.6.1 主件，vc168 未含）。

### 件⑤（RD）后台任务日志可见性——她点名要的

- **RD1**：`proactive_trace.log` **文件化**（filesDir，256KB 轮转，与总结日志同规格），并补齐 8 段链路点位——**每段一行**：①入口(工作流/设备事件/定时) ②FGS 启动成败（旧代码裸崩，改优雅退出+留痕） ③取时结果（含 null 与回退） ④claim 成败**及占用方** ⑤请求发出 ⑥首包 ⑦每次工具调用与结果 ⑧落库/完成/异常。**晨信工作流跑一夜，早起导出即可定位死在哪段，不用插线。**
- **RD2**：设置页统一入口「**导出后台任务日志**」——总结日志 + proactive_trace 两份一起分享；无记录时如实提示（不再出误导文案）。
- **RD3**：`trigger_proactive_message` 的 output 措辞修正——「主动消息服务已启动（**异步执行，最终结果见后台任务日志**）」：它是 fire-and-forget，workflow_runs 的 SUCCESS 只覆盖 8 段链路第 1 段，不再让裸 SUCCESS 误导成「信已写完」。

## 💬 她点名的两大关心 · 答复

- **特殊 token：能改好**。上面五层 + 两个机制修正，逃逸假设①~④全部有对应层接住，不依赖单点确诊。
- **缓存命中：本版零负作用、略偏正面**。全部改动不碰「请求组装/提示词结构」——源头清洗只动模型的*输出*流，不动发出去的*输入*；唯一改变历史内容的是存量清污，清污后**第一次**请求前缀变化（一次 cache miss），之后前缀更干净稳定（污染 token 不再随历史反复上行）。真正要护 KV cache 的是 beta.2 的 X1 注入位，不在本批。

## ✅ 装机验收（关键六条 + 晨信过夜取证）

1. **树影下跨窗口**：大窗口成功总结一次后，切到小窗口聊天、闲置到点 → 小窗口时间线应正常出总结（修前必锁死）
2. **内容拒收**：若总结模型连续输出超长 → 日志见 REJECT 缩窗重试；连挂 5 次 → 时间线见「⏸️ 已暂停」提示（不再全天无声）
3. **token 三场景**：工具调用后续写 / 大窗口 / 多上下文 —— 正文与思考流不再出现 `<|…|>`；老消息里的存量污染抽查清零
4. **导出入口**：设置 → 系统工具 →「导出后台任务日志」两份日志一起分享；总结日志含 FAIL/SKIP 两类原因
5. **晨信过夜**：工作流跑一夜 → 导出 proactive_trace.log 发树——8 段链路完整或明确死在哪段
6. **常规回归**：保活/插件/主动消息/无崩溃
